# Developing an Autonomous Agent Framework

This repository contains the implementation and experimental evidence for the MSc project **Developing an Autonomous Agent Framework: Integrating LLM-based Reasoning with Reinforcement Learning for Task Execution**.

The project investigates whether high-level procedures generated by a Large Language Model (LLM) can guide a Proximal Policy Optimisation (PPO) executor in a stateful finance environment. The LLM provides a procedural prior; PPO remains the decision-maker and can select any available action.

## Final Experimental Conditions

The final experiment compares four conditions:

| Condition | Guidance in policy input | Procedural reward bonus |
| --- | ---: | ---: |
| PPO baseline (`NONE`) | No | No |
| LLM + PPO Input (`INPUT`) | Yes | No |
| LLM + PPO Reward (`REWARD_SHAPING`) | No | Yes |
| LLM + PPO Input + Reward (`INPUT_AND_REWARD`) | Yes | Yes |

The final five-seed experiment uses seeds:

```text
10, 24, 33, 42, 50
```

The base finance state is encoded as 13 values. Input-guided modes append an 8-value one-hot guidance vector, producing 21 policy inputs. Guidance never masks or removes actions.

## Running the Final Finance Experiment

Use separate terminals for MongoDB, the backend, Ollama and training where required.

### 1. Start MongoDB

Start the local MongoDB service or confirm that the configured MongoDB Atlas instance is reachable.

### 2. Start the backend

```bash
cd backend_server
npm start
```

Keep the backend running.

### 3. Start Ollama for guided experiments

```bash
ollama serve
```

The PPO baseline does not require LLM inference, but the three LLM conditions do.

### 4. Verify the backend

From the repository root with the final-framework Python environment active:

```bash
python backend_server/test_backend_environment.py
```

The test harness checks authentication, reset/state behaviour and the finance workflow endpoints and writes an Excel log under `backend_server/logs/`.

### 5. Verify the agent framework

```bash
cd agent_framework
python -m pytest tests
```

### 6. Run an individual experiment

Examples:

PPO baseline:

```bash
python main.py train --agent ppo --episodes 1000 --eval-episodes 100
```

LLM input guidance:

```bash
python main.py train --agent llm_rl --guidance-mode input --episodes 1000 --eval-episodes 100
```

LLM reward shaping:

```bash
python main.py train --agent llm_rl --guidance-mode reward_shaping --episodes 1000 --eval-episodes 100
```

LLM input + reward shaping:

```bash
python main.py train --agent llm_rl --guidance-mode input_and_reward --guidance-bonus 1.0 --episodes 1000 --eval-episodes 100
```

A single run can also override the base seed:

```bash
python main.py train   --agent ppo   --seed 42   --episodes 1000   --eval-episodes 100
```

`--experiment-name` changes the experiment prefix while the logger still appends the run/timestamp suffix:

```bash
python main.py train   --agent llm_rl   --guidance-mode input_and_reward   --seed 42   --experiment-name llm_input_reward_seed_42
```

### 7. Run the complete configured multi-seed suite

The current `main.py` exposes the experiment suite through the `run-all` subcommand:

```bash
python main.py run-all
```

This runs all four experiment conditions for every configured seed:

```text
PPO baseline
LLM Input
LLM Reward Shaping
LLM Input + Reward
```

By default, `run-all` uses the seed list and experiment defaults loaded from `config/.env` / `config.py`.

You can override the seed list directly:

```bash
python main.py run-all --seeds 10 24 33 42 50
```

You can also override the number of training/evaluation episodes:

```bash
python main.py run-all   --seeds 10 24 33 42 50   --episodes 1000   --eval-episodes 100
```

To explicitly set the procedural guidance bonus used by the reward-guided conditions:

```bash
python main.py run-all   --guidance-bonus 1.0
```

To choose the name of the combined suite-result folder:

```bash
python main.py run-all   --suite-name final_dissertation
```

By default, the suite stops when an individual experiment raises an error. To continue with later conditions/seeds instead:

```bash
python main.py run-all   --continue-on-error
```

A complete explicit final-style command is therefore:

```bash
python main.py run-all   --seeds 10 24 33 42 50   --episodes 1000   --eval-episodes 100   --guidance-bonus 1.0   --suite-name final_dissertation
```

The suite creates the normal per-run outputs plus per-seed and all-seed comparison workbooks, raw records and figures.


## Command-Line Interface

`agent_framework/main.py` has two subcommands:

```text
train    Run one PPO or LLM-PPO experiment.
run-all  Run all four conditions across multiple seeds and build combined reports.
```

### `train` options

```text
--agent {ppo,llm_rl}                 Required.
--episodes N                         Override training episodes.
--eval-episodes N                    Override deterministic evaluation episodes.
--experiment-name NAME               Optional run-name prefix.
--seed SEED                          Override the single-run base random seed.
--guidance-mode MODE                 none | input | reward_shaping | input_and_reward
--guidance-bonus VALUE               Non-negative procedural reward bonus.
```

For baseline PPO, guidance is always forced to `NONE` and the guidance bonus is ignored/disabled regardless of LLM defaults.

### `run-all` options

```text
--seeds S1 S2 ...                    Override configured experiment seeds.
--episodes N                         Training episodes per condition/seed.
--eval-episodes N                    Evaluation episodes per condition/seed.
--guidance-bonus VALUE               Bonus for reward-guided conditions.
--suite-name NAME                    Combined-result folder name.
--continue-on-error                  Continue after a failed run.
```

The CLI validates that episode counts are positive, guidance bonuses are non-negative, suite seeds are non-negative and the seed list contains no duplicates.

## Reproducibility

For a reproducible comparison:

- keep the experiment condition unchanged except for the intended guidance mode;
- use the same seed set across all four conditions;
- keep the LLM model and Ollama configuration fixed;
- reset the finance sandbox at the start of every episode;
- do not manually modify MongoDB during a run;
- keep the backend and agent seed flow aligned;
- use deterministic evaluation separately from stochastic PPO training;
- record configuration, checkpoints, logs and raw metrics for every run;
- baseline PPO must always have zero guidance bonus.

## Preliminary Proof of Concept

The `POC/` folder contains the early feasibility study. It used a 5 × 5 GridWorld, Stable-Baselines3 PPO and Llama 3 movement hints. Matching a valid LLM hint produced an auxiliary positive reward, and repeated LLM responses were cached.

The POC suggested that LLM guidance could improve the reward trajectory, but frequent low-level LLM calls increased wall-clock time. That observation directly motivated the final architecture, where the LLM creates reusable high-level procedures rather than being queried at every PPO state transition.
